# 脚本开发规范（游戏社区签到助手 · 通用签到框架）

> 本框架**不内置任何游戏脚本**，所有签到能力都由「脚本插件」提供。
> 你（或 AI）只需按本规范写一个 index.js，即可接入任意游戏/社区签到。

---

## 1. 插件是什么

一个插件 = 一个**文件夹**，里面至少一个 index.js。文件夹名随便取（建议用中文，如「鸣潮」，方便查找）；插件内部用英文 id 做唯一标识（与文件夹名无关）。

    插件目录结构：
    <插件id>/
    └── index.js          # CommonJS 模块，module.exports 一个插件对象

安装方式（放进去即自动读取，无需安装）：
把插件文件夹放进「脚本」目录（打包版 = 免安装版目录内/脚本，如 游戏社区签到助手-免安装版-vX.Y.Z/脚本；开发版 = 仓库根/脚本），
点「账号管理」→「管理游戏脚本」→「🔄 刷新」即自动加载。

## 2. GamePlugin 契约（module.exports 字段表）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| id | string | ✅ | 唯一标识：小写/数字开头，仅 a-z0-9_-，长度 1-32；无需与目录名一致（目录名可用中文） |
| name | string | ✅ | 显示名（账号卡片标题），非空 ≤24 字符 |
| community | string | 否 | 社区名（卡片副标题），缺省回退 name |
| icon | string | 否 | 卡片图标（emoji/短文本 1-4 字符），缺省 🎮 |
| meta | object | 否 | `{ version, author, homepage, login }`。**当前只有 `version` 会被界面消费**（游戏脚本列表里显示），其余三项仅作插件自述，框架不读 |
| defaultEnabled | boolean | 否 | 安装后默认启用态；缺省 false（需用户在「账号管理」页显式开启） |
| defaultTime | string | 否 | 默认签到时间 HH:mm；缺省用全局默认时间（06:00） |
| loginMethods | array | ✅ | 登录方式元数据，非空，见 §3 |
| signin | function | ✅ | 签到执行，见 §5 |
| describeCredential | function | 否 | 账号摘要，见 §6 |
| onRemove | function | 否 | 卸载前清理钩子，见 §6 |
| genFingerprint | function | 否 | 生成设备指纹，见 §3.3。需要指纹的登录接口（如塔吉多）应提供 |
| reuseFingerprint | function | 否 | 复用已有凭据里的指纹，见 §3.3 |

> ⚠️ 上面标 ✅ 的四项（`id`、`name`、`loginMethods`、`signin`）缺任一项，注册表校验直接失败、插件不会被加载。
> 另外：只有列在 `core/game-registry.js` 转发白名单里的函数名会被框架取用；白名单外的导出（例如自定义工具函数）
> 主进程拿不到。要新增框架级钩子，必须同时改那份白名单。

## 3. loginMethods：登录方式

每种登录方式一个对象，kind 是受限词汇表：**`sms` / `web` / `paste` / `gui`（四种）**
（词汇表定义在 `core/game-registry.js` 的 `KINDS`；新增 kind 需同时改 game-registry、
`main.js` 的 `LOGIN_KIND` 与 IPC、`renderer/app.js` 的 `KIND_LABEL`/`methodKind`/面板模板，以及本文档）。

> 框架只认这四种 kind：`qr`（扫码）与 `password`（密码）不在词汇表里，渲染层也没有对应面板。
> 各插件头部注释写明了为什么没用它们（崩铁：扫码的 panda 端点已失效；异环：密码接口可用但未接入）。
> 真要新增一种 kind，得同时改上面列出的全部位置——`core/game-registry.js` 的 KINDS 注释里有清单。

通用字段：

| 字段 | 说明 |
|---|---|
| id | 方式唯一 id（数组内不重复） |
| kind | 上面 4 种之一；不写时框架按 `needs` 推断（见 `game-registry.js` 的 `guessKind`），但**建议显式写** |
| label | 登录方式显示名（tab 标签）。**界面直接用这个 label**，不会被框架的兜底表覆盖 |
| needs | 表单需求（如 `['mobile','code']`）。用途是「插件没写 kind 时推断 kind」；**面板形状由 kind 决定，不是按 needs 逐项生成**（渲染层的面板是静态写死的） |
| hint | 面板提示文案 |
| help | `{ links:[{url,text}], steps:[] }` —— 官方网址 + 小白分步操作说明；建议必填 |

### 3.1 各 kind 的回调（元素内自带，或模块级同名导出，二选一）

**元素内回调一律是 `(ctx, args)` 两参**，`args` 是对象——不要把字段直接当第二个参数写，
否则拿到的是整个对象（把字段直接写成 `paste(ctx, raw)` 会让 token 变成 `"[object Object]"` 并静默失效）。

| kind | 元素内回调 | args 形状 | 模块级回调（框架按此顺序传参） |
|---|---|---|---|
| paste | `paste(ctx, args)` | `{ raw }` | `loginByPaste(raw[, fp, oldCred])`，无则回落 `loginByCookie(raw)` |
| sms | `sendSms(ctx, args)` + `smsLogin(ctx, args)` | `{ mobile }` / `{ mobile, code }` | `sendSmsCode(mobile[, fp])` + `loginBySms(mobile, code[, actionType 或 fp])` |
| gui | `guiOpen`（可选） | — | 框架起本地登录页（`core/browser-login.js` + `core/login-gui.html`）并用系统默认浏览器打开；页面里的各 tab 最终调的还是本插件的模块级回调，所以**模块级至少要有 `loginBySms` / `loginByPaste` / `loginByCookie` 之一** |
| web | `webMeta`（见 §3.2） | — | — |

`ctx` 由框架的 `makeLoginCtx()` 构造，含 `{ fp, actionType, oldCred }`：
- `fp` = 设备指纹，取自 §3.3 的复用/生成逻辑；插件不需要指纹时忽略即可。
- `oldCred` = 同游戏已有账号的凭据（供粘贴登录复用 uid/refreshToken）。**注意现状：框架建了 ctx 后并未给它赋 oldCred，所以目前恒为 null**（`main.js` 的 `makeLoginCtx`），插件不要依赖它。

> ⚠️ **`loginBySms` 第三个参数的歧义（真实踩过的坑）**：框架按 `ctx.actionType` 是否存在决定传什么——
> 有则传 `actionType`，无则传 `fp`。而 `ctx.actionType` 只来自 `sendSmsCode` 返回值里的 **`sessionData`** 字段
> （`main.js` 只读 `r.sessionData`，不读顶层字段）。崩铁旧的短信登录就是因为把 `action_type` 放在返回值**顶层**、
> 框架读不到 → `actionType` 恒空 → 登录必然抛错。若你的插件需要两阶段标识，**必须放在 `sessionData` 里返回**：
> `return { ok: true, sessionData: { actionType: '...' } }`。

### 3.2 web（网页登录窗口，自动提取登录态）—— 推荐给新手降低门槛

kind:'web' 的登录方式须带 webMeta：

    webMeta: {
      loginUrl: 'https://官方登录页',
      title: '窗口标题（可选）',
      hint: '窗口内操作提示（可选）',
      // 在页面上下文执行的 JS（返回可 JSON 序列化的登录态对象）
      extractScript: '(async () => { /* ... */ return { token: ... }; })',
      // 判定登录态是否可用（在主进程执行）
      validate(extracted) { return { usable: true, reason: '' }; },
      // 把登录态组装成 credentials（在主进程执行，可为 async）
      buildCredentials(extracted) { return { token: ... }; },
      // 不可用时的降级提示 + 可切换的替代方式
      degradation: { text: '网页登录不可用，请改用…', fallbackKinds: ['sms','paste'] },
    }

**关键点（HttpOnly Cookie）**：页面里的 document.cookie 读不到 HttpOnly 的 cookie（如米游社 cookie_token_v2）。框架已在 extracted 上附加 _cookies（主进程通过 session.cookies 读到的完整 cookie，含 HttpOnly），validate / buildCredentials 可直接用它：

    validate(extracted) {
      const c = extracted._cookies || [];          // [{name, domain, value}]
      return { usable: c.some(x => x.name === 'cookie_token_v2' && x.value), reason: '' };
    }

安全：_cookies 值只留在主进程，不会下发到页面/渲染层。

> ⚠️ **`validate` 与 `buildCredentials` 是运行时必填**，但注册表加载期**只校验 `webMeta.loginUrl`**。
> 也就是说：漏写这两个函数，插件能正常加载、能出现在界面里，直到用户点「网页登录」时才报
> 「插件 webMeta 缺少 validate/buildCredentials」（`main.js` 的 `handleWebOpen`）。别被「加载通过」骗了。

### 3.3 设备指纹（genFingerprint / reuseFingerprint）

有些社区的发码/登录接口要带设备标识，且**同一账号反复换设备标识会触发服务端风控**。约定：

    genFingerprint()          → { deviceid, openudid, vendorid }   // 生成一份新指纹
    reuseFingerprint(oldCfg)  → 同上                                // oldCfg 有效则原样复用，否则退回生成新的

框架侧 `main.js` 的 `makeLoginCtx()` 取值顺序：**先扫同游戏已有账号的 credentials 借指纹**
（`existingFingerprint()`），借不到才调插件的 `reuseFingerprint(null)` / `genFingerprint()`。

> 框架还按游戏持久化一份指纹（`storage.getFingerprint` / `storage.saveFingerprint`，落
> `<dataDir>/fingerprints.json`），所以 `makeLoginCtx()` 的取值顺序是
> **①同游戏已有账号凭据里的指纹 → ②持久化的指纹 → ③新生成并立即持久化**：
> 首次登录之后同一游戏一直复用同一份，不会每次换新；卸载该游戏时指纹一并清除。
>
> 为什么要在意这件事：同一账号反复更换设备标识容易触发服务端风控（表现为收不到验证码），
> 而首次登录没有已有账号可借指纹。若出现收不到验证码，先查 fingerprints.json 是否被清空/损坏、
> 是否多机共用同一数据目录，再怀疑服务端。

## 4. 凭据（credentials）

登录回调返回的凭据对象（token/cookie/密码等），由框架整体加密落盘（Windows DPAPI）。
- 每个账号独立一份 credentials，登录/签到内不要跨账号共享全局缓存。
- 不要打印/回显 token/cookie/密码明文。

## 5. signin(account) 与 SignResult

    async function signin(account) {
      // account = { id, game, nickname, enabled, credentials, lastResult }
      // 可能还有框架扩展字段（如 time=账号自定义签到时间 HH:mm，）——插件应忽略未知字段，
      // 账号级时间由框架侧调度，插件无需感知。
      return { result: SignResult, credentialsUpdate: null };
    }

SignResult：

| 字段 | 类型 | 说明 |
|---|---|---|
| ok | boolean | false = 需告警（失败/过期/部分失败） |
| level | string | success / info / warn / error |
| status | string | success / already / failed / auth-expired / skipped |
| title | string | 一句话摘要（含 emoji），卡片「最近结果」展示 |
| lines | string[] | 详细日志行 |
| reward | string | 今日奖励文案（可空） |
| **accountName** | string | **建议必填**。写进当日结果（`logs/YYYY-MM-DD.json`）的昵称字段，签到日历与 QQ 日报都靠它显示账号名（`core/runner.js` 取 `result.accountName`，缺失才回落 `account.nickname`）。三个官方插件都返回它——漏了不会报错，但日历/日报里会变成空昵称 |
| roleName | string | 可空。游戏内角色名（当前框架只在 signin 抛异常的兜底路径里用到） |
| userId | string | 可空。社区 uid（同上） |

约定：
- 登录过期务必返回 status:'auth-expired'（UI 引导重登/重贴）。
- credentialsUpdate：需持久化的凭据增量（续期 token、自动补全的 userId 等），返回部分字段对象，框架与磁盘最新凭据合并写回；无需则 null。
- 异常可抛出，框架会捕获转成「脚本异常」并继续其它账号。
- **框架会对 `title` 与 `lines` 逐条做脱敏**（`core/redact.js`：token/cookie/JWT/查询串里的敏感值打码）再写日志与上屏，插件不必自己脱敏，但也别指望原文能完整显示。

## 7. 最小可跑示例（粘贴 token + 签到骨架）

保存为任意目录（如 demo-community/，目录名可与 id 不同）：

    'use strict';
    module.exports = {
      id: 'demo-community',
      name: '示例社区',
      community: '示例游戏',
      icon: '🧪',
      meta: { version: '1.0.0', author: '你' },
      defaultEnabled: false,          // 安装后默认不自动签到
      loginMethods: [
        { id: 'paste', kind: 'paste', label: '粘贴 token', needs: ['token'],
          hint: '粘贴示例社区 token',
          help: { links: [{ url: 'https://example.com/', text: '官网' }],
            steps: ['① 打开官网登录；', '② F12→Network 复制 token；', '③ 粘贴并保存。'] } },
      ],
      loginByPaste(raw) {
        let token = String(raw || '').trim();
        if (token.startsWith('{')) { try { token = (JSON.parse(token) || {}).token || ''; } catch (e) {} }
        if (!token) throw new Error('token 为空');
        return { token, loginAt: new Date().toISOString() };
      },
      async signin(account) {
        const cred = account.credentials || {};
        // ↓ 换成真实接口调用（https + token 请求头）
        return {
          result: { ok: true, level: 'success', status: 'success', title: '✅ 签到成功（占位）',
            lines: ['✅ 示例社区签到成功！'], reward: '示例奖励 ×1',
            accountName: account.nickname || '示例账号' },   // 日历与 QQ 日报靠它显示账号名，别漏
          credentialsUpdate: null,
        };
      },
    };

## 8. 校验规则与常见报错

加载时框架逐字段校验（实现见 `core/game-registry.js` 的 `validatePlugin`），失败则**只拒绝这一个插件**、
其它插件照常加载，错误会列在「管理游戏脚本」弹窗里。完整报错清单：

| 报错原文 | 修复 |
|---|---|
| 插件导出不是对象（require 失败或未 module.exports） | 检查是否 `module.exports = {...}`、有无语法错误 |
| 缺少必需导出 id（String） / name（非空 String） / loginMethods（非空数组） / signin（Function） | 补上对应字段 |
| id 非法：须小写/数字开头、仅 a-z0-9_-、长度 1-32 | 换个合法 id（目录名无所谓，可为中文） |
| name 过长（≤24 字符） | 缩短显示名 |
| community 必须为非空 String（可省略） | 要么整个省略，要么给非空字符串 |
| icon 必须为 1-4 字符展示文本（可省略） | emoji 或短文本，别超长 |
| loginMethods[i] 缺少 id ／ id 重复 | 每个方式给唯一 id |
| loginMethods[i] label 必须为非空 String | 补 label |
| loginMethods[i] 无法解析 kind（缺 kind 字段且 needs 不识别） | 显式写 kind（推荐），或给可识别的 needs |
| loginMethods[i] kind 非法：xxx；词汇表=sms/web/paste/gui | 用词汇表内的 kind |
| sms 需 sendSms 回调或模块级 sendSmsCode（smsLogin / loginBySms 同理） | 元素内或模块级补回调，见 §3.1 |
| paste 需 paste/loginByPaste/loginByCookie | 三者给一个 |
| gui 需主进程浏览器登录支持（模块需提供 loginBySms/loginByPaste/loginByCookie 之一） | 模块级至少给其中一个 |
| web 需 webMeta.loginUrl | 补 webMeta，见 §3.2（注意 `validate`/`buildCredentials` 加载期**不**校验，运行时才报错） |

## 9. 测试

- 本地快速自测（在 `脚本/` 目录下执行，`<目录名>` 换成你的插件文件夹名）：

      node -e "require('./<目录名>/index.js').signin({credentials:{}}).then(r=>console.log(r))"

- 应用内：插件放进脚本目录 →「账号管理」→「管理游戏脚本」→「🔄 刷新」→ 加账号 → 登录 →
  点账号旁「立即签到」→ 到「签到日历」页下方的「📄 运行日志」展开看结果（没有独立的日志页）。
- 不想污染正式数据：启动时加 `--data-dir=<临时目录>`（隔离设置/账号/日志）；
  脚本目录默认仍指向真实的「脚本」目录，要一起隔离再加 `--scripts-dir=<临时目录>`。

## 10. 安全边界

- 插件 = 主进程本机代码（require 执行），只装可信来源。
- 凭据整体加密，绝不把明文打进日志/console/README。
- 框架仅操作「签到助手-*」前缀的 Windows 计划任务，不碰其它任务。
